## 1. ゲームの概要・目標

### コンセプト

大量に出現する敵を倒し、経験値を集め、レベルアップ時に攻撃や能力を選択して強化していくゲーム。

ステージ構築のセンスに依存しないよう、基本的には固定アリーナでゲームが成立する設計とする。敵の種類、攻撃方法、強化・進化の組み合わせ、短時間での成長体験を中心にボリュームと独自性を作る。

### 目標プレイ時間

- 1プレイ：約3分を目標
- 発表デモ：3～5分以内にゲームの面白さが伝わること
- 長時間プレイしないと面白さが分からない設計は避ける

### 制作上の前提

- 開発者はUnityとC#の初心者。新しい仕組みは段階的に実装し、Inspectorでの設定手順も説明する。
- 既存機能を壊さないよう、変更前に関連ファイルを確認する。
- 実装状況とUnity上の動作確認状況を分けて管理する。実装状況は開発段階の進行を基準にし、ユーザーから個別の動作報告を求めない。
- ある機能の実装を終えて次の開発段階へ進んだ場合、前段階の機能は「完了」とする。Unity上での動作確認が未実施でも、実装状況を「未検証」に戻さない。
- Unity上の動作確認が必要な事項は、実装状況とは別に「動作確認上の注意」として記載する。実際に確認していない動作を確認済みと表現しない。
- コード変更はGitHubの `main` を基準に行う。ローカルだけに存在する変更がある場合は、上書き前に必ず確認する。

### 2.2 操作方式・難易度

操作難易度とゲーム難易度は別々に設定する。

**操作難易度**
- EASY：最も近い敵を自動照準し、自動発射。
- NORMAL：マウス方向へ照準し、自動発射。照準補助あり。
- HARD：マウス方向へ照準し、左クリックしたときに発射。照準補助は弱い。

**ゲーム難易度**
- EASY / NORMAL / HARD
- 敵の移動速度、HP、出現間隔、最大出現数に倍率を適用する。

現在は `GameSettings` が設定画面をOnGUIで表示し、PlayerPrefsへ設定を保存する実装になっている。

### 2.3 攻撃システム

| 攻撃 | 状態 | 仕様 |
|---|---|---|
| エネルギー弾 | 完了 | 初期攻撃。敵に向かって弾を発射する。敵に命中するとダメージ |
| 回転オーブ | 完了 | プレイヤーの周囲を回転し、敵との接触でダメージ |
| 衝撃波 | 完了 | 一定間隔でプレイヤー周囲の敵に範囲ダメージ |
| 雷撃 | 完了 | 最も近い敵に雷撃し、近くの敵へ連鎖ダメージ |
| メテオ | 完了 | 敵が最も密集している場所を自動で狙い、着弾予告の赤い円の後に隕石を落として範囲ダメージ |

エネルギー弾にはシアンの残光トレイルと、水色の命中パーティクル演出がある。回転オーブは青い発光、衝撃波はシアンから紫へ抜けるリング、雷撃は白青色、メテオは紫色の予告リングと発光隕石で表現する。

### 2.4 レベルアップ時の強化候補

現状、レベルアップ時に利用可能な候補から最大3つをランダムに提示する。選択中は `Time.timeScale = 0` でゲームを停止する。候補表示部分はスクロール可能。

**デバッグ操作（Unity Editor / Development Buildのみ）**
- 画面右上の `DEBUG` ボタンでパネルを開く。
- 入力欄に0以上の整数を入力し、「経験値を設定」で現在経験値を置き換える。
- 「経験値を加算」で入力した数値を現在経験値に加算する。
- タイマー操作は独立した `DEBUG TIME` パネルを画面左下に表示し、`+10秒` / `+30秒` / `+60秒` で進める。
- 同パネルの「倍速にする（2x）」でゲーム全体を2倍速にでき、「倍速を解除（1x）」で通常速度へ戻せる。Unity Editor / Development Build限定。レベルアップ・タイトル画面・リザルトなどの一時停止は維持し、再開後に選択した速度へ戻る。再挑戦時は1倍速へリセットする。経験値パネルの高さ・レベルアップ選択画面の表示に影響されない。
- レベルアップ選択中（`Time.timeScale = 0`）でも、タイマーデバッグ操作から経過時間を直接進められる。
- 設定・加算後に必要経験値以上になった場合は、通常のレベルアップ選択画面が開く。余剰経験値がある場合は強化選択後に次のレベルアップへ進む。
- 通常ビルドにはデバッグパネルを含めない（`UNITY_EDITOR || DEVELOPMENT_BUILD` 条件）。

- エネルギー弾：威力、連射速度、弾速、射程
- 回転オーブ：オーブ数、威力、回転速度
- 衝撃波：範囲、威力、発動間隔
- 雷撃：威力、連鎖数、発動間隔
- メテオ：隕石数、爆発範囲、威力、発動間隔
- 新しい攻撃の取得：回転オーブ、衝撃波、雷撃、メテオ

攻撃の取得・強化は `PlayerExperience.cs` が管理する。新しい攻撃を追加するときは、このファイルの候補生成と選択処理の両方を更新する。

**分岐強化・進化システム（実装段階完了）**
- 5種類の攻撃それぞれに2種類の分岐強化を用意し、どちらか一方を選ぶ。
- 分岐強化は攻撃ごとに1回だけ選択できる。選ばなかった分岐は同じプレイ中には取得できない。
- レベルアップ時に「進化コア」を取得できる。所持上限は3個で、画面上部に所持数を表示する。
- 分岐強化済みで、通常の数値強化を合計2回以上取得した攻撃は、進化コア1個を消費して進化できる。
- 個別進化：レールエネルギー、オービタルストーム、ノヴァウェーブ、チェインテンペスト、メテオレイン。
- エネルギー弾と雷撃を両方所持し、両方が分岐強化済み・通常強化2回以上の場合、特殊進化「プラズマキャノン」を選択できる。進化コア1個で両方を同時に進化させ、さらにエネルギー弾の威力・連射性能と雷撃の威力・連鎖性能に追加ボーナスを与える。
- 進化・分岐強化は既存攻撃の性能を強化する方式で、操作キーや操作難易度は増やさない。
- 進化候補は通常の3択に混ざって抽選される。条件を満たしても、候補に出ない場合は次のレベルアップで再抽選される。

## 2.5 ビジュアルデザイン（NEON ARENA・初期実装）

デザイン方針：近未来ネオン、エネルギー戦士、円形アリーナ、電子音楽。

- アリーナ：暗い円形フロア、シアン／紫の発光リング、放射状ライン、外周ライト柱をランタイム生成する。
- プレイヤー：暗色アーマー、シアンの胸部コア・バイザー・装甲ラインを持つ人型シルエットをランタイム生成する。
- 通常敵：暗紫色の機械生命体に赤い発光コアを配置する。
- ボス：大型の紫色装甲と青白いコアを持つシルエットにする。
- 現段階はUnity標準プリミティブによる仮モデル。専用3Dモデル・テクスチャ・Bloomを導入する際に差し替えられるよう、当たり判定と表示モデルを分離している。
- アリーナは `RuntimeInitializeOnLoadMethod(AfterSceneLoad)` で自動生成するため、`SampleScene.unity` の編集やInspectorでの手動配置は不要。
- `NeonArenaVisuals` は時間経過に合わせて外周ライトの発光を強める。

### 2.6 効果音（プロシージャル生成）

`SoundManager` が起動時に効果音用AudioClipをC#から生成し、AudioSourceで再生する。音声ファイルのインポート、Prefab配置、Inspectorでの参照設定は不要。SoundManagerは自動生成され、シーンをまたいで維持される。

| イベント | 効果音 |
|---|---|
| エネルギー弾発射 | 短い高音の電子パルス |
| 敵への命中 | 短い低めの電子音 |
| 敵撃破 | 上昇する電子音 |
| プレイヤー被弾 | 低音のノイズ混じりの衝撃音 |
| レベルアップ | 4段階で上昇するチャイム |
| 通常強化 | 短い決定音 |
| 攻撃の進化・特殊進化 | 音程が大きく上昇する専用音 |
| 衝撃波・雷撃・メテオ | 攻撃ごとに異なる電子音 |
| ボス登場・ボス攻撃 | 低音の重い警告音 |
| クリア・ゲームオーバー | それぞれ異なる終了音 |

音量はSoundManagerのAudioSourceで一括管理し、現状は初期値0.38。BGMは `MusicManager` が別途合成して再生する（下記）。効果音はAudioListenerを持つカメラが有効であることを前提とする。

### 2.7 BGMと画面演出

- `MusicManager`：128BPM・Am-F-C-Gの8小節ループを起動時にC#から合成し、自動再生する。通常時と、残り30秒のボス戦で別ループ（ハイハット増・ベース変化・リード追加）に切り替える。レベルアップ選択中など時間停止中は音量を下げ、クリア／ゲームオーバー後はさらに下げる。音声ファイルやInspector設定は不要。
- `ScreenFlash`：画面全体を一瞬光らせる。被弾（赤）、レベルアップ（シアン）、ボス登場（紫）で使用。`ScreenFlash.Trigger(色, 秒, 濃さ)` でどこからでも呼べる。時間停止中も動作する。

### 2.8 UIのネオン統一

- `NeonUI`：各 `OnGUI` の先頭で `NeonUI.Apply()` を呼ぶと、ボタン・ウィンドウ・ボックス・文字入力が暗い背景＋シアンの発光枠のスタイルになる（タイトル・強化選択・リザルト・難易度設定・デバッグ表示に適用）。HUD用のパネル・ゲージ・影付き文字の描画関数も提供する。
- HUD：画面上部中央にレベル・経験値ゲージ・進化コア（3個）、画面右下に残り時間・撃破数・HPゲージを表示する。HPは残量で緑→黄→赤紫に変化し、ボス戦（残り30秒）は時間表示とパネルが赤紫になり「BOSS PHASE」を表示する。
- 新しいUIを追加するときは、`OnGUI` の先頭で `NeonUI.Apply()` を呼び、色は `NeonUI` の定数（Cyan / Violet / Magenta / Green）を使うこと。

### 2.10 敵の種類

`EnemyType`（`EnemyAI.cs`）で4種類を定義し、`EnemySpawner` が進行度（加速後）に応じて出現を抽選する。

| 種類 | 出現開始 | 特徴 |
|---|---|---|
| Grunt | 最初から | 基本。まっすぐ追う |
| Runner | 0.12 | 小型（0.8倍）・速度×1.7（プレイヤーの1.1倍が上限）・HP×0.5・接触ダメージ×0.6 |
| Shooter | 0.30 | 距離5.5～9mを保ち、2.2秒ごとに弾（`EnemyProjectile`）を撃つ。HP×0.8 |
| Brute | 0.50 | 大型（1.7倍）・速度×0.65・HP×4・接触ダメージ×2・経験値4 |

- 出現確率は進行度とともに上がる（Runner 10→25%、Shooter 8→18%、Brute 5→12%）。残りはGrunt。
- 種類ごとのモデルは `NeonCharacterVisuals.BuildEnemy(EnemyType)`、能力は `EnemyAI.Configure(EnemyType)` で設定する。
- シューターの弾は距離判定（Collider不要）。リスタート時に残った弾は `GameSessionManager.RestartRun` で削除する。
- 新しい種類を追加するときは、`EnemyType` に追加し、`BuildEnemy`・`Configure`・`ChooseEnemyType`・`GetBodyScale`・`GetHealthScale`・`GetExperienceValue` に対応を足す。

### 2.9 ゲームの進行ペース（調整値）

3～5分の発表時間に収まるよう、進行を速めている。値はInspectorで調整できる（新しい項目名のため、シーンに保存済みの古い値は引き継がれない）。

- レベルアップ（`PlayerExperience`）：最初の必要経験値は `startExperienceToNextLevel` = 3、増加率は `experienceGrowthRate` = 1.22（必要経験値は 3, 4, 5, 7, 9, 12, 15…）。
- 敵の強化（`EnemySpawner`）：進行度を `difficultyRampSpeed` = 1.7 倍に加速し、約106秒で最大の強さに達する。最大時の倍率は、生成間隔 ×0.35、敵の最大数 ×2.5、敵のHP ×2.8、移動速度 ×1.35（ただし敵の移動速度はプレイヤーの90%を上限とする）。序盤の生成間隔は1.5秒、最大数は14体。
- ゲーム難易度（EASY/NORMAL/HARD）の倍率は、上記に重ねて掛かる。
- 難しすぎる、または簡単すぎる場合は、`finalEnemyCountScale` と `finalEnemyHealthScale` を最初に調整する。

### 実装上の注意

- 敵の検索には `EnemyHealth.ActiveEnemies`（生存中の敵の登録簿）を使う。攻撃スクリプトで `FindObjectsByType<EnemyHealth>` を毎フレーム呼ばないこと。通常敵の数は `EnemyAI.ActiveCount` で取得する。
- 倒された敵が同フレーム内に一覧に残る場合があるため、検索時は `IsAlive` も確認する。
- 線・弾の軌跡に使うMaterialは、攻撃のたびに `new Material` せず、クラスごとの `static` なMaterialを共有する（色は頂点カラーで指定）。
- 敵の表示モデル（`NeonCharacterVisuals`）を後から生成した場合は、`EnemyHealth.RefreshRenderers()` を呼んで被弾フラッシュの対象を取り直す。
- Unity 6のRigidbodyでは速度に `linearVelocity` を使用している。
- Input Systemを使用している。旧Input Manager前提のコードを不用意に追加しない。
- `GameSettings.Instance` が存在しない場合に備え、一部スクリプトは標準倍率へフォールバックする。
- `PlayerExperience` はプレイヤー本体に追加する。現在の実装では、レベルアップ時に `PlayerAutoAttack` 等の攻撃コンポーネントを同じGameObjectまたは子から取得する。
- `PlayerController` が `PlayerHealth` を自動追加し、`GameSessionManager` は起動時に自動生成されるため、これら2つはHierarchyへ手動追加しなくてよい。
- 敵はプレイヤーに接近すると1秒間隔で10ダメージを与える。プレイヤー側には0.35秒の共通無敵時間がある。
- 新攻撃はレベルアップ時に `gameObject.AddComponent<T>()` でプレイヤーに追加する設計。
- 回転オーブ・衝撃波・雷撃は現状、自動で攻撃する。個別の手動発動キーはまだない。
- 衝撃波の攻撃判定は `Physics.OverlapSphere`、雷撃の対象検索は `FindObjectsByType<EnemyHealth>` を使用する。雷撃は1回の攻撃中に敵一覧を1度だけ取得し、連鎖先の検索で使い回す。
- エフェクトは現状コードからランタイム生成するため、専用Prefabを用意しなくても試せる設計。ただし見た目・負荷は後で調整する。

## 7. 設計方針・今後の実装ルール

- 基本攻撃は5種類を目標とする：エネルギー弾、回転オーブ、衝撃波、雷撃、メテオ。
- 最初からすべての攻撃を持たせず、初期攻撃はエネルギー弾1種類。レベルアップで新しい攻撃を取得する方式。
- レベルアップ時の選択肢は原則3択。
- Unity Editor / Development Buildでは、PlayerExperienceの右上にあるDEBUGパネルから経験値を任意の整数に設定・加算できる。
- 操作難易度とゲーム難易度を分離する。
- 初心者でもプレイできるEASYを用意する一方、NORMAL/HARDでは照準や操作による判断が生まれるようにする。
- 1プレイ約3分で攻撃の取得・強化・成長を体験できるようにする。
- ステージ制作の負担を増やさず、敵の種類・攻撃の組み合わせ・進化・演出でゲームの深さを出す。
- 新機能は小さく分けて追加し、追加のたびに関連する既存コードとの整合性を確認する。
- C#ファイルを追加・移動した場合、Unity側でコンパイルが通ることを確認する。Unityが生成する `.meta` ファイルの扱いにも注意する。
- バランス調整用の数値は、可能な限り `[SerializeField]` にしてInspectorから変更できるようにする。
